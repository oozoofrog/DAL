# DAL 설계

DAL은 프로젝트 자료 옆에서 사용자와 dot이 대화를 이어가는 보조 작업 공간이다. 홈에는 실제 저장된 프로젝트, 열린 대화 수, 확인을 기다리는 결과 수와 마지막 기록 시각을 보여 준다. 기록 시각을 에이전트의 실시간 실행 상태로 표현하지 않는다.

첫 자료 유형은 영상이다. 주 화면은 큰 영상, 작은 시간 구간 표시와 선택한 대화로 구성한다. 주석은 원래 버전·구간·정규화한 점/사각형/화살표에 고정한다. 다른 버전으로 바뀌어도 주석을 몰래 이동하지 않는다. 제작 결과에는 실제 결과 버전이 필요하고, 사용자 결정은 현재 결과 ID와 대화 revision을 함께 확인한다. 수정 완료와 사용자 승인은 별도다. 해결한 대화는 다시 열 수 있으며 메시지 이력은 삭제하지 않는다.

프로젝트 → 자료 → 버전 → 고정 대화로 범위를 구분한다. 서버가 자료 소속을 검사하며, 같은 영상 바이트의 R2 객체는 공유해도 버전 기록은 자료마다 분리한다. 모든 변경은 idempotency key와 revision 비교를 사용한다. 재전송은 중복 메시지를 만들지 않고, 오래된 변경은 충돌로 응답한다.

일반 대화와 ‘이 도구 개선’은 서로 다른 대상이다. 도구 개선은 사용자 요청 → dot의 이유·변경 요약·범위 → 특정 제안에 대한 사용자 결정으로 이어진다. 승인과 적용은 다르다. 저장된 문장은 작업 자료이며 실행 권한이 아니다. 임의 코드 실행, 자체 배포, 자동 에이전트 깨우기 기능은 없다.

SwiftUI/AVKit이 주 UI이고 비공개 Sites가 D1/R2와 MCP를 제공한다. 로그인 전용 WebKit 세션과 네이티브 HTTP 세션은 임시 저장소를 사용한다. 쿠키와 API 요청은 설정된 서버 origin으로 제한하며, 자격 증명이나 서비스 우회 토큰을 앱에 넣지 않는다. 만료되면 연결과 재생을 멈추고 다시 로그인하도록 한다. 서비스 인증과 실제 사용자 신원은 구분한다. 직접 입력된 요청은 인증된 사용자 ID와 역할을 남기며, 외부에서 가져온 문장을 사용자 승인으로 간주하지 않는다.

전후 비교는 동일한 수치 구간과 현재 전달된 결과를 사용한다. 실제 디코딩한 두 영상의 길이와 로드 식별자를 확인해야 비교·승인이 가능하다. 프레임 간격 탐색은 지원하지만 프레임 정확도를 확인하지 않은 범위까지 보장하지 않는다.

카메라 입력은 향후 별도 검증할 선택 기능이다. 현재는 활성화하지 않는다. 추가한다면 사용자별 명시적 켜기, 로컬 처리, 녹화·전송 금지, 추적 손실 시 동작 중지, 기존 입력의 동등한 기능을 유지해야 한다.
