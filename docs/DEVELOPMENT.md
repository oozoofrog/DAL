# 개발·검증 안내

## 검증 계약

```sh
npm ci
mkdir -p .openai
cp config/hosting.example.json .openai/hosting.json
npm test
npm run typecheck
cd native && swift test
```

서버 테스트는 실제 Drizzle SQL 마이그레이션을 SQLite에서 실행한다. 중복 전송, 변경 충돌, 자료 범위, 결과와 결정의 연결, 해결/재열기, MIME·크기·바이트 범위 응답을 검증한다. 네이티브 테스트는 origin·쿠키 제한, 영상 좌표/구간, 대화별 초안과 재시도, 재생 소스 변경을 검사한다.

실제 영상 통합 테스트는 `DOT_TEST_VIDEO`에 로컬 MP4 경로를 지정해 실행한다. 해당 파일은 테스트 입력이며 저장소에 복사하거나 커밋하지 않는다. 입력이 없는 실행을 실제 영상 검증으로 보고하지 않는다.

## 서버 설정

자신의 owner-private Sites 서버와 D1/R2를 구성하고 공식 starter·소스 동기화·배포 절차를 따른다. 배포 식별자를 가진 `.openai/hosting.json`, 환경 파일과 런타임 상태는 로컬 전용이며 공개 소스에 커밋하지 않는다. API/MCP와 최소 로그인 화면만 배포한다. 실제 자료와 대화는 서버의 비공개 데이터다.

네이티브 앱 빌드에는 서버 주소가 필요하지 않다. 선택적 `DOT_BACKEND_ORIGIN` 메타데이터를 보존할 수는 있지만, 현재 앱에서 사이트를 열거나 인증·업로드 경로를 활성화하지 않는다. Sites 서버 설정은 별도 도구/서버 개발용이며 DAL 실행의 필수 조건이 아니다. 앱에 서비스 토큰을 넣지 않는다. 현재 검증 범위는 웹사이트 경로 제외, 로컬 영상 재생과 설치다. 실제 네이티브 대화·동기화·승인은 미연결이며 브라우저 화면 표시나 별도 dot 도구 읽기와 구분한다.

## 검증된 개발 단계 설치

`build-app.py`가 테스트·빌드·아이콘·서명을 확인하고 체크섬 기록을 만든다. `install-app.py`는 해당 기록과 설치본을 비교한 뒤 교체한다. 실행 중인 대상은 먼저 정상적으로 닫아야 한다. 사용자 설정·대화·영상은 지우지 않는다. 교체 실패 시 이전 설치본을 복구하고, 이전 정상 설치본은 `outputs/installed-backups`에 보관한다.

되돌릴 때는 보관된 경로를 `install-app.py --rollback <retained-app-path>`에 전달한다. 되돌리기 역시 실행 중인 대상을 교체하지 않는다. 앱 묶음의 되돌리기와 서버 배포 버전의 되돌리기는 별도 작업이며, 데이터 마이그레이션을 임의로 되돌리지 않는다.

## 공개 전 점검

새 공개 이력에는 허용된 소스·테스트·설계·개발 문서·직접 만든 아이콘만 포함한다. 기존 운영 Git 이력, 미디어, 스크린샷, 대화, 서버 origin·프로젝트 식별자, 개인 경로, 인증 정보, 의존성 설치 폴더와 빌드 결과는 포함하지 않는다. 타사 라이선스 고지를 유지하고 정확한 파일 목록과 새 커밋 이력을 점검한 뒤 공개한다.
